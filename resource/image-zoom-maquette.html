Technical Notes

Interaction design

  • Human perception is inconsistent with lateral motion and vertical motion, or browser coordinate spaces and expectations of them. I have inverted the Y axis in this demo, so it behaves like a software app, not a flight sim. For a production UI, maybe this should be a config setting.
  • Currently, many mobile features have zoom in to look, but automatically revert after the touch is released. I copied this approach in the #zoom3 demo. However it is less useful if you are trying to read and copy-type a serial number in fly-spec-3 font off a brochure.
  • The #zoom3 doesn't let you choose the center point of the zooming, so isn't setup for very large images eg city maps. I think I ought to extend the #zoom3 to have hot edges to change that. Not added as that means the zoom needs to be a local state and not transitory. #TODO. For systems where zoom is used often, there should be some performance analysis to preserve battery life.
  • Image software on mobile implements often touch rotate support, but I don't think rotate is relevant here. A spiral motion with diverging finger gap is still read as a zoom.
  • For production code, probably there is should be modality for haptic, and modality for WIMP inputs, as different interactions to deliver the same result. Removing unnecessary controls on mobile is a good idea (ie the big-screen version).
  • Some further notes for UX and zoom 1
  • #TODO As a later edition, I think I need to add a sigil for “image that supports zoom has focus now”, and disable other touch events ~ most urgently for scroll ~ until the zoom is completed. I need to innovate a clear set of symbols, I didn't find one during reading.
  • If I open a larger image (larger than my screen) directly in the browser, I get scroll bars by default. However the interaction between 3rd wheel button to zoom and scroll vertically isn't well thought out, and it fights. If I had a nice-UX view-image-from-URL widget, I would use it for this action. Existing tech and research

  • This tech isn't brand-new and should be widely reliable and available. You will note the emphasis on how to use it and when to use zoom features. I have implemented this in production more than once, I assume you will have too.
  • A standard technique to preserve quality is for a Zoom interaction to use a higher resolution image, so users get more data via their zooming. Not done in the maquette, but double buffering is easy (suggest downloading the large image in advance of zooming for lower interaction latency). JS for this would be routine.
  • Possibly I should use a double-tap to activate the zoom capacity (and the larger image) 2. The double-tap is a clear signal the user is focussing on this thing, and so adjust the layout to foreground it.
  • The haptic zoom means user need to have clean screen etc to ensure a good experience.
  • There is no implementation difference between zoom to see a new hair style on a “profesh” model (MPEG video) and zoom to look at an invoice (PDF), to check the delivery address. There are many people looking at delivery addresses and similar needs. When I bought a new kitchen in 2017, the delivery drivers had poor control of PDF invoices on their work phones.
  • I like image zoom not affecting any text in the background (ie whole page zoom), as these are different goals. This is increasing common in recent Design Systems.
  • To be able to zoom an asset, you could use: CSS transform scale, CSS zoom, for SVG XXX. The components below, are an easier means to access this. As far as IMG elements should have width/ height, if these values are increased this will deliver zoom effect. For SVG, see svg-format-notes, the expected screen space is set in the meta data header, these can be changed to effect good quality zoom, and ZVG supports good clipping effects ts as well.
  • I was expecting to set a touch-action CSS statement, as I did in other projects, a public example git. However there doesn't seem to be any need yet.
  • .
  • Many older systems have zoom item to whole of current window. This was mostly used before zoom CSS instruction, and is an incomplete user-journey, especially for mobile. If the large image is opened in a tab by itself, the OS level scroll and zoom features can be used. However a dedicated interaction should be easier and faster to operate, and therefore encouraged.
  • After that, and with fixed layouts, there was a button to have a larger view (not dynamic, and no control on centre of zoom). I don't think that this historic option is useful.

  • Another persons demo for presentation adjustment 6. They have successfully used purely CSS. This author favours stateless interactions that revert to initial state.
  • A demo with worked example pinch events V Morneau, using plain JS. Obviously this is only for haptic interfaces. However work by turriate kind-of-works for mouse and touch.
