I see random benchmarks floating round that say 1) JS is much faster than TS, 2) JS is much faster than XYZ compiled language. I think this proves that benchmarking is hard; the need for clear and simple UI/UX is very strong; and “there are lies, damned lies and statistics”. Thirdly these are the benchmarks that lack a execution date or version of language used. Please read several large books on “how computers execute software”, and “how computers convert near English languages into Assembly” before replying [so we will be using a common terminology].
I like this benchmark, as it includes dates and versions 1, and ooh look compiled languages are now faster than JS. Also note log scale. A second benchmark from 2020, that is just Golang, Elixir and Node 2, these are fairly old versions of each language, but it is labelled correctly.

I am listing availability of various tools on server operating systems. It is hard to discover global market success rate for server OS. I see multiple stats that seem to conflate “North America” with “the entire planet”. According to 3 4 the most common project bases are Debian (under the Ubuntu label), and Redhat (under Centos label). I'm not sure if *BSD is omitted as “not Linux”, or if its just less common.

Note the boundaries between “compiled” and “not compiled” languages are fuzzy. The most visible example being that many of my unit tests are written in Typescript, but I never have a visible compile step for them. There are online REPL for many compiled languages e.g. 5 6, both Golang running inside a sandbox. Perl, Python and PHP do have 'object code' ~ like a compiled Clib ~ but it isn't always persisted to disk. For long-life processes it should be encouraged to-do so. For teaching purposes some people echo C code source into a bash process pipeline (echo, compiler, linker, chmod, and auto execute) ~ with a bit more sophisticated UI this would seem an interpreted language.

Each one of these languages should be used with:

  • an IDE (fairly common, with plugins)
  • a task tracker/ user journey tracker/ CTO mumblings tracker (common across each language)
  • version control (common across each language)
  • a test framework
  • a package manager
  • a lint/ prettier tool
  • best compile tools
  • docs tools
  • profilers ~ I tend to focus on DB profiling, as this is a larger slow down. But I include this section for completeness.
