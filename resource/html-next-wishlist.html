Concept

From the position that the internet would be better if “essential SPA in JS” wasn't mentioned or thought. In 2007, there where problems, and JS-SPA was a good solution THEN. Today there are many solutions, so JS-SPA isn't essential.

A JS minimalist approach leads to better accessibility on average, as there is more control to build #a11y and RWD and so-on. Less JS is routinely leads to less bandwidth needed, and faster load times. Storing application solutions in formats other than JS means it is easier to localise/ internationalise ~ IMO and anecdotal experience.
Disclaimer: I use a large amount of JS and TS. There is no architecture reason that “a webapp” has less default platform features available than a Microsoft generated-code install wizard or help feature (I am aware of herding-cats problems to get every browser and language developer to agree to solving mere app-dev cost problems).

Requests

However, developing systematic and holistic HTML5 apps and services would be easier and faster if devs had:

  • The 'open with' protocol looked less hacky. Currently it looks dodgy/ security issue to open a Zoom call from a HTML email, it should be a standard tech by now. This request is mostly UI changes, not much engineering. If a user has Zoom installed, and registered it as a known media type, there should be no warning popups. Etc, etc for other video stream services.
  • Forms had a cancel Button type. If we use less HTTP requests, we need 'Cancel' not an HTTP0.9 Anchor to other page. This should work similar to a Details.open=false. As forms are mobile centric and load with a user profile injected, a reset Button is less useful than during 1997. I don't think I have ever used a reset Button. I can implement this in JS, each time for each form, but an architecture solution would be better. Most SPA libraries do not cleanly offer this simple feature.
  • There was a common agreed format for client-side localisation persistence. This item ignores a traditional DB in a server. Probably any early edition would use YaML. I see Vue has i18n block 1 2 in a SFC. There is common i18n framework 3 npmjs, that React also integrates with.
  • Various HTML validators in use are updated to understand DIALOG element (and other more recent elements). #leSigh.
  • Role attrib was allowed to have multiple items, example: a UL of LI and navigation elements is a list role, and its navigation role. The List role is probably less important in this example.
  • The ARIA attribs were better wired in to the rest of HTML and CSS, Also better known states for absent ARIA atrtibs.
  • Forms in HTML supported encoding of JSON, to allow POST straight to a REST API. I am kind-of-doing this via JS fetch() and JSON features. See a related maquette, if everything is JSON ~ svg-in-api-response-maquette ~ which isn't the best choice, but is widely supported.
  • SEARCH HTML semantic element was globally supported. As of 2024: this is available in Safari 17+
  • SPOILER HTML element, behaves similar to DETAILS/ SUMMARY 4.
  • Some semantic element for ERROR or SHOWERROR. This should be a type in HTML so it can be cleanly and consistently reported. I can patch with ARIA attribs, but there isn't a single well-known usage. Error reporting should be consistent and widely applied. Ideally every version of microsoft outlook should be forcibly updated to show these tags correctly.
  • As there are many digital exam platforms, having a CODE text entry element would make these much better. As a normal person I do not do type tabs, my IDE injects them for me and manages indent. However in a exam, tab will change UI component, and I have to type them.
  • Web manifest file format extended to support listing ALL files deployed, as in common in other languages.
  • Maybe out of scope, but JS tools being encouraged to report unknown values in config files as unknown values. This would match other programming languages, and encourage faith by junior devs that JS was deterministic, not ritualistic.

Some of these are my initial idea, some are imports from others. This list will be updated.
